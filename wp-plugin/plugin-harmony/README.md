# هماهنگ‌ساز افزونه‌ها — Plugin Harmony

افزونه‌ای برای وردپرس که:

1. سایت را تحلیل می‌کند (وردپرس، PHP، زبان، HTTPS، پیوند یکتا، کش شیء، سرور، ووکامرس، حجم محتوا).
2. همهٔ افزونه‌های فعال را شناسایی می‌کند — هم با نام فایل، هم با کلاس/ثابت/گزینه، تا تغییر نام پوشه تشخیص را خراب نکند.
3. برای هر «قابلیت» (نقشهٔ سایت، کش صفحه، فایروال، پشتیبان‌گیری، ضداسپم، …) یک افزونهٔ مرجع انتخاب می‌کند.
4. تضادها را گزارش می‌دهد: دو افزونهٔ سئو، دو فایروال، دو کد آمار، دو صفحه‌ساز، دو افزونهٔ چندزبانه.
5. تنظیمات هر افزونه را با افزونه‌های دیگر و با نیاز واقعی سایت هم‌راستا می‌کند و **قبل از نوشتن، از مقدار فعلی نسخهٔ پشتیبان می‌گیرد**.
6. هنگام فعال‌شدن افزونهٔ جدید (`activated_plugin`)، در درخواست بعدی مدیر سایت را دوباره اسکن می‌کند و تنظیمات افزونهٔ تازه را با بقیه هماهنگ می‌کند.
7. اسکن روزانه (Cron) ناهماهنگی‌های ایجادشده پس از به‌روزرسانی افزونه‌ها را ترمیم می‌کند.

---

## نصب (از همان صفحهٔ افزونه‌های وردپرس)

افزونه کاملاً استاندارد بسته‌بندی شده است؛ هیچ تنظیم دستی پیش از نصب لازم نیست.

### روش ۱ — بارگذاری زیپ در پیشخوان (ساده‌ترین)
1. فایل `wp-plugin/plugin-harmony.zip` را از مخزن بردارید (یا با `bash wp-plugin/build.sh` بسازید).
2. در وردپرس بروید به **افزونه‌ها ← افزودن افزونه ← بارگذاری افزونه**.
3. فایل زیپ را انتخاب کنید ← **اکنون نصب کن** ← **فعال‌سازی**.
4. از منوی کنار، **«هماهنگ‌ساز افزونه‌ها»** را باز کنید.

زیپ یک پوشهٔ `plugin-harmony` دارد، فایل اصلی `plugin-harmony.php` با هدر کامل
(`Plugin Name`, `Version`, `Requires PHP`, `Text Domain`) و بدون BOM است؛ اسکریپت
`build.sh` این موارد را قبل از تحویل بسته بررسی می‌کند.

### روش ۲ — کپی پوشه
پوشهٔ `plugin-harmony` را در `wp-content/plugins/` کپی و از صفحهٔ افزونه‌ها فعال کنید.

### روش ۳ — WP-CLI
```bash
wp plugin install /path/to/plugin-harmony.zip --activate
```

پس از فعال‌سازی، از منوی مدیریت **«هماهنگ‌ساز افزونه‌ها»** را باز کنید.

## سرعت: چرا سایت را کند نمی‌کند

| موقعیت | هزینه |
|---|---|
| بازدیدکننده (فرانت‌اند) | **صفر هوک، صفر کوئری، دو فایل کوچک** — افزونه پیش از هر کاری برمی‌گردد |
| پیشخوان وردپرس | یک بررسی سبک برای اعلان؛ نقشهٔ تنظیمات فقط در صفحهٔ خودِ افزونه ساخته می‌شود |
| صفحهٔ افزونه | یک بار ساخت نقشه در هر درخواست (با حافظهٔ درون‌درخواستی، نه تکرار) |
| کرون | یک رویداد روزانهٔ `phm_daily_scan` |

کارهای انجام‌شده برای همین هدف:

- **بارگذاری تنبل کلاس‌ها:** هر کلاس با `spl_autoload_register` تنها وقتی نیاز باشد بارگذاری می‌شود؛ برنامه‌ریز، رابط مدیریت، فهرست دانش و نویسندهٔ تنظیمات روی درخواست عادی هرگز parse نمی‌شوند.
- **بازگشت زودهنگام روی فرانت‌اند:** هوک‌های فعال‌سازی، به‌روزرسانی، کرون و پنل فقط در `wp-admin`، `wp-cron.php` و WP-CLI ثبت می‌شوند.
- **حافظهٔ درون‌درخواستی برای نقشه:** ساخت دوبارهٔ نقشه در همان درخواست هیچ گزینه‌ای را دوباره نمی‌خواند؛ هر تغییر (تنظیمات، اسکن، اعمال، بازگردانی، قاعدهٔ سفارشی) حافظه را باطل می‌کند.
- **کش خواندن‌ها:** پروفایل سایت ۵ دقیقه و نام نمایشی افزونه‌ها یک روز کش می‌شوند تا خواندن هدرِ فایل‌ها تکرار نشود.
- **بدون autoload:** تاریخچه، نسخه‌های پشتیبان و دفترچهٔ اسکن با `autoload = no` ذخیره می‌شوند و روی `alloptions` سایت بار نمی‌گذارند (روی نصب‌های قدیمی هم در فعال‌سازی اصلاح می‌شود).
- **حجم محدود:** ۱۰۰ دستهٔ تاریخچه، حداکثر ۳۰۰ ردیف در هر دسته، ۲۰ نسخهٔ پشتیبان آخر.
- **بدون فایل فرانت‌اند:** CSS و JS فقط در صفحهٔ خود افزونه بارگذاری می‌شوند.
- **بدون گوش‌دادن به AJAX/REST:** هیچ درخواست ایجکس یا REST سایت را درگیر نمی‌کند.

## نصب و بررسی بسته

```bash
bash wp-plugin/build.sh
# خروجی: "بررسی بسته: موفق"
```

اسکریپت این موارد را خودکار بررسی می‌کند: یک پوشهٔ سطح‌بالا با نام درست، وجود فایل اصلی،
هدرهای `Plugin Name` / `Version` / `Text Domain`، نبود BOM، نبود تگ پایانی `?>`
و نبود فایل‌های توسعه (`node_modules`, `tests`, `.git`) داخل بسته.

## سه حالت کاری

| حالت | چه می‌کند |
|---|---|
| **فقط پیشنهاد** (پیش‌فرض) | هیچ چیزی خودکار نوشته نمی‌شود؛ فقط نقشهٔ تغییرات و تضادها نمایش داده می‌شود. |
| **اعمال خودکار کم‌خطر** | قواعد با ریسک کم، هنگام فعال‌سازی افزونهٔ جدید و در اسکن روزانه خودکار نوشته می‌شوند. |
| **اعمال خودکار کامل** | قواعد کم‌خطر و متوسط خودکار نوشته می‌شوند (مثلاً فشرده‌سازی CSS، زمان‌بندی پشتیبان‌گیری). |
| **غیرفعال** | هیچ خواندن/نوشتنی انجام نمی‌شود. |

قواعد «دستی» (high) در هیچ حالتی خودکار اعمال نمی‌شوند.

## چرا «تنظیم خودکار همهٔ افزونه‌ها» سه لایه دارد؟

وردپرس API استانداردی برای تنظیمات افزونه‌ها ندارد. هر افزونه ساختار خودش را در جدول `options` (یا جدول اختصاصی خودش) ذخیره می‌کند: یوآست آرایهٔ تودرتو، AIOSEO رشتهٔ JSON، Wordfence جدول جدا، LiteSpeed چند گزینهٔ وابسته، WPForms کلیدهای متغیر بین نسخه‌ها.

نوشتن کورکورانه در این ساختارها = خرابی تنظیمات کاربر. بنابراین:

- **لایهٔ ۱ — نوشتن خودکار:** فقط افزونه‌هایی که ساختارشان در فهرست دانش تعریف شده و **کلید هدف از قبل در سایت وجود دارد** (هستهٔ وردپرس، Yoast، WooCommerce، UpdraftPlus، Smush، WP Rocket، Autoptimize).
- **لایهٔ ۲ — پیشنهاد دستی:** افزونه‌هایی که نوشتن اشتباه در آن‌ها آسیب واقعی می‌زند (Wordfence، Solid Security، LiteSpeed، WPML/Polylang، SMTP، صفحه‌سازها، آمار).
- **لایهٔ ۳ — قاعدهٔ سفارشی:** برای هر افزونهٔ دیگر، از تب «قواعد سفارشی» نام گزینه و مسیر کلید و مقدار را وارد کنید؛ بدون کدنویسی.

هیچ ادعایی دربارهٔ «تنظیم کامل و بی‌خطای هر افزونهٔ ناشناخته» وجود ندارد؛ چیزی که وجود دارد: تشخیص، هماهنگ‌سازی، پیشنهاد و بازگردانی امن.

---

## مدل ایمنی

- **فقط کلیدهای موجود:** اگر گزینه یا مسیر کلید در سایت نباشد، قاعده رد می‌شود (نه اینکه مقدار جدید ساخته شود).
- **فهرست ممنوعهٔ سخت:** `active_plugins`، `siteurl`، `home`، `permalink_structure`، `users_can_register`، `default_role`، `admin_email`، رمزهای SMTP، `cron`، `rewrite_rules` و … هرگز نوشته نمی‌شوند.
- **پشتیبان قبل از نوشتن:** مقدار کل هر گزینه یک بار ذخیره می‌شود (حداکثر ۲۰ دستهٔ آخر، قابل تنظیم).
- **تأیید بعد از نوشتن:** مقدار واقعی دوباره خوانده می‌شود؛ اگر افزونه مقدار را با فیلتر `sanitize` رد کرد، در تاریخچه «افزونه نپذیرفت» ثبت می‌شود.
- **بازگردانی یک‌کلیکی** برای هر دسته.
- **حالت پیش‌فرض = فقط پیشنهاد.**

```

│   ├── class-phm-settings.php    ذخیرهٔ تنظیمات و حالت‌ها
│   ├── class-phm-registry.php    فهرست دانش (Recipe) + برچسب خانواده/قابلیت
│   ├── class-phm-profile.php     پروفایل سایت
│   ├── class-phm-detector.php    شناسایی افزونه‌ها و مالکیت قابلیت‌ها
│   ├── class-phm-planner.php     ساخت نقشهٔ تغییرات و تضادها
│   ├── class-phm-applier.php     نوشتن امن، پشتیبان، بازگردانی
│   ├── class-phm-advisor.php     پیشنهاد برای افزونه‌های ناشناخته
│   ├── class-phm-values.php      مقادیر وابسته به بافت (مثل صفحات ووکامرس)
│   ├── class-phm-admin.php       رابط مدیریت فارسی
│   ├── class-phm-cron.php        اسکن روزانه
│   ├── class-phm-cli.php         فرمان‌های WP-CLI
│   └── recipes/                  فهرست دانش: core, seo, cache, performance,
│                                 security, forms, ecommerce, backup, analytics,
│                                 redirects, mail, comments, multilingual,
│                                 maintenance, builder
└── assets/                       CSS و JS مدیریت
```

## توسعه

Recipe جدید:

```php
add_filter( 'phm_recipes', function ( $recipes ) {
	$recipes['my-plugin'] = array(
		'id'           => 'my-plugin',
		'name'         => 'My Plugin',
		'family'       => 'seo',
		'priority'     => 20,
		'plugins'      => array( 'my-plugin/my-plugin.php' ),
		'capabilities' => array( 'sitemap' => 30 ),
		'rules'        => array(
			array(
				'id'     => 'my_sitemap_off',
				'label'  => 'خاموش‌کردن نقشهٔ سایت تکراری',
				'option' => 'my_plugin_settings',
				'path'   => array( 'sitemap', 'enabled' ),
				'value'  => false,
				'risk'   => 'low',
				'conditions' => array( 'capability_secondary' => 'sitemap' ),
			),
		),
	);
	return $recipes;
} );
```

شرط‌های پشتیبانی‌شده: `profile`، `not_profile`، `capability_primary`، `capability_secondary`، `option_filled`.

فیلترها و اکشن‌ها:

| نام | نوع | کاربرد |
|---|---|---|
| `phm_recipes` | filter | افزودن/ویرایش Recipe |
| `phm_plan_changes` | filter | تغییر نقشهٔ نهایی |
| `phm_protected_options` | filter | گسترش فهرست گزینه‌های ممنوعه |
| `phm_capability_owner` | filter | تعیین دستی افزونهٔ مرجع یک قابلیت |
| `phm_after_apply` | action | پس از نوشتن هر دسته |

## خط فرمان

```bash
wp harmony scan                 # پروفایل، خانواده‌ها، تضادها
wp harmony preview              # پیشنهادها بدون نوشتن
wp harmony preview --family=seo
wp harmony apply                # اعمال همهٔ پیشنهادها
wp harmony apply --family=cache --dry-run
wp harmony rollback phm_20260101120000_1234
wp harmony log
```

## محدودیت‌های شناخته‌شده

- Recipeهای افزونه‌های تجاری (Yoast Premium، Smush Pro، Rank Math Pro) با همان گزینه‌های نسخهٔ رایگان بررسی می‌شوند؛ اگر نسخهٔ شما کلید را نداشته باشد قاعده رد می‌شود (خطا نمی‌دهد).
- تنظیمات ذخیره‌شده در جدول اختصاصی (Wordfence، Redirection، Gravity Forms، BackWPup) خوانده نمی‌شوند و فقط پیشنهاد دستی دریافت می‌کنند.
- اگر افزونه‌ای مقدار را با `sanitize_callback` سخت‌گیرانه رد کند، در تاریخچه «افزونه نپذیرفت» می‌بینید؛ این رفتار عمدی است.
- تشخیص «مالک قابلیت» بر اساس امتیاز داخلی هر Recipe انجام می‌شود؛ با فیلتر `phm_capability_owner` می‌توانید آن را دستی تعیین کنید.
